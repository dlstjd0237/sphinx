# Sphinx

Sphinx is an open-source Node.js CLI that helps developers retain understanding of code written with coding agents. Git checkpoints require the human to answer bounded questions about observable behavior and design consequences before a protected push proceeds.

The Git hook determines when a check is required. A separate Pi SDK reviewer session investigates immutable Git evidence without the development conversation and generates questions and private rubrics. Pi owns the agent session, tool loop, and native compaction. Sphinx supplies restricted tools, project context, model transports, a bounded archive of exact evidence, and per-request usage accounting. A fresh independent audit checks proposed questions and answer keys against their exact evidence before display. Independent grading uses that evidence and the rubric. Failed investigations preserve Pi entries and evidence so retries can resume; provider errors never approve a change. Incorrect answers lead to an explanation and a new scenario about the same concept. The blocking Git hook serves a token-protected loopback questionnaire while the original Git process waits. macOS opens it in a background tab for terminals and coding agents, without activating Terminal or minimizing another application, and in front for GUI Git clients; native Windows opens it in front; other desktops print its local URL. Human answers go directly to Sphinx, while coding agents receive status only. Git verifies the exact receipt and continues its original operation. Native Codex/Claude MCP forms and Pi dialogs remain fallbacks for queued checks; an exited operation cannot be resumed. Manual terminal checks remain available.

Core invariants: ignored or sensitive file contents must never be read or sent to a model; background preparation cannot approve code; completion is bound to the exact source, destination, policy, and project context. Preserve existing Git hooks and agent settings. Keep model requests bounded, make route and paid-model choices explicit, and reserve calls for auditing and grading. Correctable protocol errors may be repaired within the same allowance; extending that allowance or retrying provider failures requires an explicit choice. Small changes need only one initial question.

The implementation is provider-neutral and uses Node.js 22.19+ with @earendil-works/pi-coding-agent and @earendil-works/pi-ai pinned to 1.2.0. Codex and Claude CLI routes remain fresh isolated model transports under Pi, using existing CLI authentication. The Pi development-client extension is separate from the embedded reviewer runtime. Other clients can use the generic Git gate and terminal check. Tests use temporary Git repositories and isolated homes with fixture evaluators. The eval runner adds curated executable Git fixtures and optional bounded live model runs; it never answers or approves real human checkpoints. Project setup belongs in .sphinxconfig, .sphinxignore, and this context file; credentials remain outside repositories.
